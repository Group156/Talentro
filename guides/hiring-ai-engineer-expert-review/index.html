Hiring an AI Engineer: Separate the Build Brief from Expert Review

Hiring for an AI project starts with the work that needs to be delivered. Building an application and judging whether its specialist outputs are useful are related tasks, but they can require different people. A clear brief helps you decide which expertise to source.

Define the engineering output

Describe the workflow, users, inputs and expected output. Specify whether the engagement covers a prototype, integration into an existing application or maintenance of a deployed service. Name the systems involved and the person who can approve access.

Agree the handover before work begins. Depending on the project, that may include source code, deployment instructions, an evaluation dataset, known limitations and operational documentation. Ask candidates to explain comparable work, their own contribution and how they tested it.

Define the subject-matter review separately

A functioning application can still produce an unsuitable specialist answer. If professional judgment is needed, describe that evaluation task explicitly. Specify the field, subfield, recent experience, country and language that matter.

For example, a hypothetical engineering assistant might need a software engineer to implement retrieval and a practising specialist to assess whether retrieved material supports the proposed answer. Neither contribution replaces the other.

Prepare representative examples

Select examples that reflect intended use, including incomplete information and cases outside scope. Give reviewers a rubric that explains what to score, what evidence to record and when to flag uncertainty. Do not ask them to invent an answer when they cannot judge the case.

Use a small shared sample to compare reviewers

Before expanding a review exercise, inspect disagreements on a shared set of examples. Clarify unclear instructions and decide how disputed cases will be resolved. Record changes to the rubric so later results can be interpreted in context.

Compare proposals on the same basis

Ask each provider to state its assumptions, exclusions, deliverables and fees against the same brief. Identify who is responsible for engineering, expert recruitment, credential checks, task coordination and final acceptance. A low headline rate does not reveal the total effort or what is included.

Availability and dates need confirmation

Agree milestones only after the provider has reviewed the required skills, project dependencies and availability. Where specialist recruitment is involved, confirm the relevant screening criteria and proposed headcount in writing. Avoid treating a generic profile or service page as proof that a particular person is available.

What to send in a first enquiry

Include the project goal, technical environment, specialist field, countries, languages, approximate task length, intended review output and preferred timing. Share a non-confidential example if it would clarify the work. Agree suitable data access arrangements before sharing sensitive project material.
